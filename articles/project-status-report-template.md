# Project Status Report Template: Weekly, Executive and Multi-Project Examples You Can Copy

*Last updated: 24 November 2026*

> **Quick answer:** A project status report template is a 1-page update with 6 sections: overall status (red, amber or green), progress since the last report, next steps, risks and issues, decisions needed, and key metrics. Most teams send it weekly, on the same day, to the sponsor and stakeholders.

A **project status report** is a short, regular update telling stakeholders whether a project is on track, what changed, and what help is needed. A good project status report template makes that update take 15 minutes to write and 2 minutes to read.

Below you will find a copyable 1-page template, weekly, executive and multi-project versions, how to use RAG status, how to set it up in Word, Excel or PowerPoint, and 7 best practices.

## What is a project status report?

It is a regular summary of a project's progress, risks and next steps, sent to sponsors, stakeholders and the team. Atlassian describes it as a way to [keep stakeholders informed about a project's progress](https://www.atlassian.com/agile/project-management/status-report) without pulling them into every meeting.

It answers 4 questions in this order:

1. Are we on track? (Status color)
2. What happened since the last update?
3. What happens next?
4. What do we need from you?

### Why are project status reports important?

They matter because they surface problems while there is still time to fix them, and they reduce the number of meetings stakeholders need to attend. Gallup reports that only [16% of US employees strongly agree their leadership communicates effectively](https://www.gallup.com/workplace/716321/leadership-communication-at-work.aspx), and a predictable written update is one of the simplest ways to close that gap on a project.

## What should a project status report include?

Include 6 core sections: summary and RAG status, accomplishments, next steps, risks and issues, decisions or help needed, and metrics. Optional sections include budget, scope changes and milestone dates.

| Section | What to write |
|---|---|
| Summary and status | 1 to 2 sentences plus red, amber or green |
| Accomplishments | 3 to 5 bullets since the last report |
| Next steps | 3 to 5 bullets for the coming period |
| Risks and issues | Each with an owner and a mitigation |
| Decisions or help needed | Specific asks, with a deadline |
| Metrics | Schedule, budget, scope or KPI numbers |

## Free project status report template (1 page)

Copy this one page project status report template into Word, Google Docs or your project wiki. Replace the bracketed text each week.

> **Project:** [Name] | **Report date:** [Date] | **Owner:** [Name]
> **Reporting period:** [Start date] to [End date]
>
> **Overall status:** 🟢 Green / 🟡 Amber / 🔴 Red
> **Summary:** [1 to 2 sentences: where we are and why]
>
> **Accomplished this period**
> - [Item]
>
> **Planned next period**
> - [Item]
>
> **Risks and issues**
>
> | Risk or issue | Impact | Owner | Mitigation |
> |---|---|---|---|
> | [Item] | High / Med / Low | [Name] | [Action] |
>
> **Decisions or help needed:** [Ask, who, by when]
>
> **Key metrics:** Schedule [on time / X days late] | Budget [X% used] | Scope [changes]

## What does a project status report look like?

Here is a filled-in example for a 12-week website migration in week 6, so you can see how short each section can be.

> **Project:** Website migration | **Report date:** 14 Nov | **Owner:** Dana
>
> **Overall status:** 🟡 Amber
> **Summary:** Content migration is 2 days behind because product pages need legal review. Launch date holds if review finishes by 21 Nov.
>
> **Accomplished:** 140 of 220 pages migrated; redirects mapped; QA plan approved.
> **Next:** Finish product pages; start accessibility testing; run load test.
> **Risks:** Legal review capacity (owner: Sam, adding a second reviewer).
> **Ask:** Approve 10 hours of external legal review by 18 Nov.
> **Metrics:** Schedule 2 days late | Budget 48% used | Scope unchanged

The whole update is under 120 words, and the sponsor knows exactly what to approve.

## What is RAG status in a project status report?

RAG status is a 3-color rating, Red, Amber and Green, that shows a project's overall health at a glance. Government IT offices publish their definitions. Missouri's IT services division, for example, rates schedule [green if completion is expected within the planned schedule](https://oa.mo.gov/sites/default/files/ITSD-Status-Report-Template.pdf), yellow if it may not be, and red if scheduling decisions are required. Define the colors once for your team so "amber" means the same thing in every report.

| Color | Meaning | Example rule |
|---|---|---|
| 🟢 Green | On track | Milestones on time, budget within 5% |
| 🟡 Amber | At risk, recoverable | A milestone may slip, plan in place |
| 🔴 Red | Off track, needs help | Milestone missed or budget over 10% |

Report the color for the project overall and, if useful, for schedule, budget and scope separately. Never mark a project green when you are privately worried. An honest amber early is worth more than a surprise red later.

## What are some project status report template examples?

The 3 most common project status report template examples are the weekly team report, the executive summary and the multi-project roll-up. Each uses the same core sections at a different level of detail.

### Weekly project status report template

The weekly project status report template is the full version above, sent every week to the team and sponsor. Keep it to 1 page and send it on the same day, for example every Friday by noon.

### Executive project status report template

An executive project status report template cuts the update to 5 lines that a leader can read in 30 seconds:

> **[Project]: 🟡 Amber**
> **Headline:** [What changed and why it matters]
> **Key milestone:** [Name], due [date], [on track / at risk]
> **Top risk:** [Risk] (owner: [name])
> **Ask:** [Decision or support needed by date]

When reporting status to executives, lead with the ask. Executives read the first 2 lines and decide whether to read the rest.

### Multiple project status report template

A multiple project status report template shows several projects in 1 table, so a portfolio manager can spot problems across the portfolio.

| Project (owner) | Status | Next milestone | Ask |
|---|---|---|---|
| [Project A] ([Name]) | 🟢 | [Milestone, date] | None |
| [Project B] ([Name]) | 🟡 | [Milestone, date] | [Ask] |
| [Project C] ([Name]) | 🔴 | [Milestone, date] | [Ask] |

Keep the top risk for each project in its own full report, and link to it from the project name.

## How do you write a project status report?

You write one in 5 steps: collect updates, set the status color, write the summary, list risks and asks, and send it on schedule. With a template, it takes about 15 minutes a week.

1. **Collect updates.** Pull completed tasks, milestone changes and new risks from your project tool and recent meetings.
2. **Set the status color.** Apply your RAG rules honestly.
3. **Write the summary last.** After filling the sections, write 1 to 2 sentences that explain the color.
4. **List risks and asks.** Each risk gets an owner, each ask gets a deadline.
5. **Send it on schedule.** Same day, same channel, every period.

### How do you report project status in agile teams?

In agile teams, report status at the end of each sprint with 4 items: sprint goal met or not, completed stories or points, what moved to the next sprint, and blockers. Burn-down or burn-up charts replace long text. Pair it with your [daily standup notes](https://lynkk.ai/blog/daily-standup-meeting) for day-to-day status.

## How do you make a project status report template in Word, Excel or PowerPoint?

You can build the template in any of the 3 common Office tools in under 10 minutes. Choose the tool based on who reads the report.

| Tool | Best for | Setup tip |
|---|---|---|
| Word or Google Docs | Written weekly updates | Save as a template; use a table for risks |
| Excel or Google Sheets | Multi-project roll-ups and metrics | One row per project; conditional formatting for RAG |
| PowerPoint | Steering committee and executive reviews | 1 slide per project with status, milestones and asks |

In Word, save the file as a Word Template (.dotx). In Excel, use conditional formatting rules that color the status cell when it says Red, Amber or Green.

## What are project status reporting best practices?

The 7 best practices are: keep it to 1 page, lead with status and asks, use the same format every time, define RAG rules, show trends, link to details, and send it on a fixed schedule.

1. **One page.** If it needs more, link to an appendix.
2. **Status and asks first.** Readers decide in the first 2 lines.
3. **Consistent format.** People learn where to look.
4. **Written RAG rules.** No debates about what amber means.
5. **Trends, not just snapshots.** Show last period's color next to this one.
6. **Links, not attachments.** Point to the plan, board and risk log.
7. **Fixed schedule.** A late report signals a project problem even when there is none.

## FAQ

### How often should you send a project status report?

Most teams send one weekly. Short or high-risk projects may need 2 updates a week, while long, stable projects can move to every 2 weeks.

### What is the difference between a status report and a progress report?

A status report shows where the project stands right now, including risks and asks. A progress report focuses on work completed against the plan over a period. Many teams combine both in 1 weekly update.

### Who should receive a project status report?

Send it to the project sponsor, key stakeholders and the core team. Keep the distribution list to people who act on it, and send executives the 5-line summary version.

### What makes a good project status report?

A good report is 1 page, leads with an honest RAG status, lists specific risks with owners, and ends with a clear ask and a deadline.

### Can you create a project status report in Jira?

Yes. Jira dashboards can show sprint progress, issue counts and burn-down charts, which cover the metrics section. You still need 2 or 3 written sentences for the summary, risks and asks.
