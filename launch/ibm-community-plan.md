# IBM: Where and What Lynkk Can Publish

> Research date: 2026-10-13. Sources are listed at the bottom. Rules on IBM sites change,
> so re-check the linked guideline pages before each first post.

## TL;DR

1. **IBM TechXchange Community (community.ibm.com)** is the only IBM property where an
   outside company can publish on its own. It takes blogs, discussion posts, library
   files and events. Blogging needs a one-time **blogging access application**, and first
   posts are moderated.
2. The hard rule: **knowledge sharing, not advertising.** Every blog must tie to an IBM
   product, integration, workflow or technical topic. A "Lynkk is great, sign up" post
   will be rejected or removed.
3. The best long-term IBM channel for a product like Lynkk is **IBM Agent Connect**
   (watsonx Orchestrate Agent Catalog). It is a marketplace listing, not a blog, and it
   needs a real integration first.
4. **ibm.com/think, IBM Developer (developer.ibm.com) and the IBM blog** are written by
   IBM staff. There is no open "write for us" route for outside companies, so skip them.

## 2. IBM Community rules that matter

From the official Blogging Guide, the Blogging in the Community page and the Netiquette page:

- **Access:** "You need an IBM Community account and blogging access to create a blog post."
  External users apply through the *Blogging in the Community* page. IBM says it reviews
  applications daily. Fill in your profile (bio + photo) before applying.
- **Join the group first.** You can only blog in a group you are a member of (blue "Join"
  button). Posts are created from the group's **Blogs** tab, then **Create New Blog**.
- **Moderation:** all first-time posts are moderated. Edits can send a post back to moderation.
- **No advertising:** "The Community is for knowledge sharing, not advertising." Netiquette:
  "Do not use the online community for self-promotion or commercial advertising." Product
  info is allowed "provided it is factual, is generally for the benefit of forum members."
- **Must relate to IBM:** each post should tie to an IBM product, workflow, integration,
  release, best practice or technical topic, and sit in the right group.
- **No teaser posts:** give the full value on the page, do not just send readers to lynkk.ai.
- **Format:** original, English, at least 350 words. An image is required. Featured image is
  landscape, at least 1200 x 600 px. Visibility "Public" so Google can index it.
- **Cross-posting:** IBM prefers the post appears on the Community first. If you reuse it
  on lynkk.ai or LinkedIn, tailor it and stagger the dates.
- **Repeat breaking the rules** can get the account and content removed.

### SEO notes

- Use a long-tail keyword phrase (3+ words) in the title, the permalink, and at least twice
  in the body. Keep the meta description under 160 characters.
- Permalink: letters, numbers and dashes only.
- In a spot check of one live community blog (Oct 2026), an external link in the body was
  served without `rel="nofollow"`. Treat that as a bonus, not a promise; it can change and
  moderators remove links that look promotional. The bigger value is that community.ibm.com
  ranks well on Google and gets cited by AI search tools for IBM-related queries.
- After publishing: share it on LinkedIn with the built-in share link, and post a short
  discussion thread in the group that links to the blog (IBM's own suggested way to promote it).

## 3. Content types that work for Lynkk

The trick is to write about the IBM side of the problem and let Lynkk appear as the worked
example, not the subject.

| Content type | Example angle for Lynkk | Best group |
|---|---|---|
| **Technical tutorial** | "Turning meeting action items into watsonx Orchestrate tasks with MCP" (only if we build and test it) | watsonx Orchestrate |
| **Architecture / how we built it** | "Designing a live voice agent that joins meetings: lessons for agent builders" | watsonx Orchestrate, AI |
| **Best practices** | "Five rules for AI agents that act after a meeting: approvals, audit trail, ownership" | watsonx Orchestrate, Automation |
| **Compliance / data residency** | "Data residency for AI meeting assistants: questions to ask before rollout" | Security, AI governance (watsonx.governance) |
| **Case study** | A customer story where meeting outcomes flow into an IBM-run workflow (needs a real customer) | Industry group that matches the customer |
| **Comparison / explainer** | "Before, during, after: mapping the meeting lifecycle to agent orchestration" | watsonx Orchestrate |
| **Video blog** | 3-5 min demo of a Lynkk + IBM workflow, embedded in a blog | Any of the above |
| **Library asset** | Downloadable "AI meeting assistant security checklist" PDF | Security |
| **Helpful answers** | Reply to threads about meeting summaries, agent memory, MCP tools, multilingual capture | Any group with those topics |

### Things to avoid

- Pricing, "start free" calls to action, feature lists with no IBM tie.
- Claiming an IBM integration, partnership or certification that does not exist yet.
- Posting the same article on several groups at once.

## 4. Suggested 30-day plan

**Week 1: set up**
- Complete the IBM Community profile: Lynkk bio, photo, link to lynkk.ai.
- Join groups: watsonx Orchestrate, AI / watsonx.ai, Automation, Security, IBM Build Partners
  Technical Group.
- Submit the blogging access application.
- Join the Agent Connect waitlist (connect.watson-orchestrate.ibm.com) and start the
  Partner Plus ISV sign-up.

**Week 2: earn trust**
- Answer 5-10 discussion threads with real help (no links unless they answer the question).

**Week 3: first blog**
- Publish one best-practices post, for example the "Five rules for AI agents that act after
  a meeting" idea, in the watsonx Orchestrate group. 600-1,000 words, one diagram, one
  mention of Lynkk as the example.
- Post a discussion thread linking to it, and share on LinkedIn.

**Week 4: second asset**
- Publish the data-residency post in the Security group, plus a PDF checklist in the Library.

**Next quarter**
- Build and test a real Lynkk tool or agent for watsonx Orchestrate (MCP makes this a
  short path), then publish the tutorial and apply for an Agent Catalog listing.
- Prepare a talk for the TechXchange 2027 call for sessions.
