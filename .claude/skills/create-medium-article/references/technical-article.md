# Technical Article

Use this reference when code, architecture, operations, or an implementation
is central to the article.

- Establish the engineering problem before showing implementation detail.
- Verify examples against the authoritative repository or label them as
  illustrative.
- Prefer one idea per snippet. Include only enough code to teach that idea.
- Explain why the code exists, its important boundary, and the consequence of
  the decision; do not narrate it line by line.
- Distinguish configurable examples such as prices, thresholds, time windows,
  and service names from universal constants.
- Cover the most relevant reliability, cost, latency, security, or maintenance
  trade-offs without forcing every category into every article.
- Link to the complete public implementation rather than pasting full files.
- Test runnable examples or report clearly when execution is unavailable.
